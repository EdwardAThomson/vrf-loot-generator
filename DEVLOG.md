# Development Log

## 2026-07-27

A major hardening and expansion day, turning the prototype into the foundation of the chain-anchored roguelike design. The day started with planning docs: an architecture write-up for the blockchain roguelike (public dungeon layout derived from a transaction hash, private VRF loot, off-chain verification), a set of code-audit questions, a roadmap, and a phased implementation plan. The audit answers then drove the big hardening commit: the VRF core was migrated from P-256 to RFC 9381 ECVRF (EDWARDS25519-SHA512-TAI over noble curves, validated byte-exact against the RFC test vectors), a soundness gap in item verification was closed (proofs were previously accepted even when paired with an unrelated output; verification now binds the proof to the supplied output and reconstructs the message from blockhash and item index), and a new sealed-loot layer added per-item commitments with a publishable manifest and selective reveal, surfaced in the UI as face-down commitment cards. Trading commitments moved to a canonical deterministic encoder so honest late reveals verify. Phase 3 followed the plan: a zustand-backed toast system replaced the last alert()/confirm call sites, and a deterministic dungeon generator (SHA-256 layout seed, sfc32 PRNG, byte-identical output per tx hash) got its own demo tab that drives sealed loot generation for the derived item count, demonstrating the public-layout / private-loot split end to end. A cleanup pass finished the day: all ESLint warnings resolved for CI-mode builds (fixing a latent stale-closure bug in the trading socket effect along the way), a persist migration that drops stale P-256 keypairs on rehydration, legacy mock-crypto demo scripts retired in favor of a TypeScript simulation over the real services, and unused crypto deps removed. The suite grew from a broken state to 13 suites / 150 tests green, plus a new 21-check headless CI harness.

**Decisions & notes:** The ECVRF migration is breaking: old P-256 keypairs are invalid, handled by a store migration rather than a hard error. Test infrastructure was consolidated onto react-scripts as the single runner (the shadowing jest.config.js and setupTests.js were deleted). Commitments are versioned and bind item identity only, deliberately excluding timestamps. Phases 1-3 of the implementation plan are complete.
